=============================
缓解拒绝服务攻击(DDoS)
=============================

拒绝服务(DoS/DDoS)既可以是恶意攻击者的蓄意打击，也可能源于突发热点、配置失误或物理线缆被挖断等非恶意事件，最终都会把系统逼向"可用性失守"。

DoS攻击本质
================

- **攻击本质** : 攻击者试图让目标服务的需求(Demand)超过其容量供给(Supply)，从而挤占合法用户的服务能力，或逼迫运营方在"烧钱硬扛扩容"与"停机承受业务损失"之间做痛苦抉择(甚至衍生出勒索型 DoS)。
- **资源不对称** : 攻击者与防御者都面临资源约束。聪明的攻击者会挑选依赖链中最薄弱的环节(DNS、网络链路、前端接入、后端数据库或高成本计算接口如搜索)，用有限资源撬动更大破坏。
- **DoS 与 DDoS 的区分** : 单机/少源可打穿的偏向 DoS（常在应用层应对）；依赖海量节点或反射放大才能生效的属于 DDoS(常在基础设施层过滤与分散)。

攻击者的常见手法与"放大攻击"原理
====================================

- 攻击者伪造受害者的源 IP 地址，向大量开放服务器(常见于 DNS、NTP、Memcached 等协议)发送小请求；
- 响应流量被"反射"到受害者 IP，且响应体积往往远大于请求体积，形成流量放大。
- 关键防御洞察: 许多放大攻击来自特定的知名源端口，因此在网络边界通过 ACL 对可滥用协议的 UDP 流量做限流/过滤，往往非常有效。

架构设计:从"共享基础设施"到"单个服务"分层设防
===============================================

流量越往系统内部走，越容易聚焦在单一瓶颈资源(带宽、CPU、内存、数据库连接)上，也越难在后端低成本消化。因此必须分层设防(Layered Defenses):

- 共享基础设施层(Shared Infrastructure):

  - **外层先拦、内层省力** : 边缘路由器限流高带宽洪峰、网络负载均衡过滤包洪水、应用层负载均衡挡住应用层异常流量，越早丢弃无效流量，越节省骨干网带宽与后端算力，还能发挥规模效应(就像多站点共享防护池能摊薄单次攻击的峰值压力)。
  - **慎把"有状态防火墙"放进第一道防线** : 维护连接跟踪表的有状态设备在面对海量伪造连接时，极易遭遇状态耗尽(State Exhaustion)；相比之下，无状态的路由器 ACL 更适合做端口与协议级边界过滤。
  - **分散打击面** : 通过 Anycast(多点宣告同一 IP)和智能负载均衡把流量分散到全球多个节点或有余量的机房，避免攻击火力像放大镜聚光一样打穿单一数据中心。

- 单个服务与业务层(Defendable Services):

  - 善用缓存与减少无效请求: 合理配置 Cache-Control 让边缘/代理层吃掉重复读请求；合并小图标、控制图片/响应体积以节省出向带宽(Egress)，同时减少合法用户的零碎请求数，降低误判为机器人的概率。

运行时缓解:精准告警与优雅降级
===============================

- **告警要"可操作"，别把正常吸收当事故** : 监控请求速率、CPU 与内存的同时，只有当需求超出容量、自动化防线已介入或需要人工介入时才触发高优先级告警(例如 SYN flood 被自动吸收时不必盲目吵醒值班人员，但连接队列告警或链路打满时就需要关注)。

- **按优先级降级** : 遇到过载或攻击时，优先保核心主链路，给低优先级任务(如批量拷贝)降 QoS，或让业务进入只读/降级模式(例如关闭评论、精简非核心功能)，保住"能看、能用"的基本盘。

建议
=========

- 边界过滤尽量轻量化、无状态，把昂贵计算和数据库连接挡在缓存、限流与前置接入层之后。
- 提前写好"降级剧本": 流量突增或遭遇攻击时，系统最怕没有优先级排序地全面僵死；提前想清楚哪些功能可以关、哪些队列可以丢，关键时刻才能稳住核心服务。
